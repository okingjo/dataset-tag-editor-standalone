# Dataset Tag Editor Standalone

[日本語 Readme](README-JP.md)

> **Independently maintained fork.** Upstream ([toshiaki1729/dataset-tag-editor-standalone](https://github.com/toshiaki1729/dataset-tag-editor-standalone)) has been inactive since **July 2024**, so this fork is maintained on its own. It adds a self-contained **uv** install (isolated from system Python), **Smart Tag Dedup** (offline rules or a local LLM), **booru tag autocompletion** (a1111-sd-webui-tagcomplete compatible), and **large-dataset performance** improvements. Run it with `launch_uv.bat` (Windows) or `webui_uv.sh` (Linux/macOS) — see the install instructions below.

This is a WebUI tool to edit training dataset for Text2Image Models.  
This is **a standalone version** of [Dataset Tag Editor](https://github.com/toshiaki1729/stable-diffusion-webui-dataset-tag-editor), which is an extension for [Stable Diffusion web UI by AUTOMATIC1111](https://github.com/AUTOMATIC1111/stable-diffusion-webui).  
**Please do not put into `extensions` folder of AUTOMATIC1111's webUI.**

![](pic/ss01.png)

It works well with text captions in comma-separated style (such as the tags generated by WD / PixAI interrogators).

Caption in the filenames of images can be loaded, but edited captions can only be saved in the form of text files.

## Difference from the Extension Version
(Pros)  
- Avoid bugs caused by specific version of gradio
- Much faster startup and running

(Cons)
- Hijacked CLIP tokenizer is not available (which has SDwebUI specific features like embedding, emphasis, …)
- No more support for old Python < 3.9


## Requirements
All dependencies are pinned in `pyproject.toml` / `uv.lock` and installed automatically by uv.

**The only thing you need to install yourself is [uv](https://docs.astral.sh/uv/).**
It downloads a private Python interpreter (3.11) and every dependency — including PyTorch
and the [ONNX runtime](https://onnxruntime.ai/) used by the wd-taggers — into this folder.
No system Python, no manual PyTorch setup, no runtime package installation.

## Installation

### Recommended: uv (isolated, no system pollution)
[uv](https://docs.astral.sh/uv/) creates a private virtual environment (`.venv/`) and keeps
**all** downloaded state — package cache, Python interpreter, model cache and temp files —
inside this folder under `runtime/`. Nothing is installed into your system Python.

1. Install uv once: <https://docs.astral.sh/uv/getting-started/installation/>
2. Start the app (uv creates the environment and installs the pinned dependencies on first run):
   - **Windows:** double-click `launch_uv.bat`
   - **Linux / macOS:** `./webui_uv.sh`

To install without launching, run `uv sync`. The pins in `pyproject.toml` / `uv.lock` are a
known-good combination for Gradio 4.28.3.

By default **CPU-only PyTorch** is installed (lightweight, works everywhere, no CUDA toolkit
required). For NVIDIA GPU acceleration, after `uv sync` run:
```sh
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
uv run --no-sync scripts/launch.py
```
(`--no-sync` keeps the CUDA build instead of restoring the locked CPU one.)

## Features
Note. "tag" means each blocks of caption separated by commas.
- Edit and save captions in text file (webUI style) or json file ([kohya-ss sd-scripts metadata](https://github.com/kohya-ss/sd-scripts))
- Edit captions while viewing related images
- Search tags
- Filter images to edit their caption by tags
  - AND/OR logic can be used in each Positive/Negative filters
- Batch replace/remove/append tags
- Batch sort tags
- Batch search and replace
  - [regular expression](https://docs.python.org/3/library/re.html#regular-expression-syntax) can be used
- Use interrogators
  - SmilingWolf's [WD Tagger](https://huggingface.co/SmilingWolf) v3 family (`wd-vit-tagger-v3`, `wd-convnext-tagger-v3`, `wd-swinv2-tagger-v3`) and the large timm variants (`wd-vit-large-v14-tagger`, `wd-eva02-large-tagger-v3`)
  - [PixAI Tagger v1.0](https://huggingface.co/pixai-labs/pixai-tagger-v1.0) (ONNX; general/character/style/copyright/meta/rating categories)
  - [Z3D-E621-Convnext](https://huggingface.co/toynya/Z3D-E621-Convnext)
  - Legacy models (WD v1/v1.4/v2, DeepDanbooru, BLIP, BLIP2, GIT) were removed — use WD v3 / PixAI for tags and the VLM captioner for natural language
- Natural-language captioning with a vision LLM (**NL & Multi Captions** tab)
  - Any OpenAI-compatible vision server (Ollama / llama.cpp / vLLM), e.g. an uncensored Qwen3.5-35B-A3B — NSFW datasets captioned without refusals
  - Per-image NL sidecars (`<img>.nl.txt`), editable in the *Edit Caption of Selected Image* tab
- Hybrid caption export for DiT trainers (**NL & Multi Captions** tab)
  - Generates `<img>.multi` caption candidates (pure tags / tags+NL / pure NL, separated by `---===---`) for kohya sd-scripts multi-caption training (Anima / MOSS), derived from the edited `.txt` tags + NL sidecars — one master caption set serves both CLIP-based (SD/Illustrious/Pony) and LLM-text-encoder (Anima/MOSS) training
- You can add Custom Tagger in `userscripts/taggers` (they have to be wrapped by a class derived from `scripts.tagger.Tagger`)
  - Some Aesthetic Score Predictors are implemented in there
- Batch remove image and/or caption files
- Smart tag deduplication: drop generic tags when a more specific one is present
  (e.g. `white thighhighs` removes `thighhighs`). Works offline with a built-in
  implication table, or via an OpenAI-compatible / Anthropic chat API.
- Booru tag autocompletion while editing captions (a1111-sd-webui-tagcomplete
  compatible): type a few letters and pick from Danbooru tags with aliases,
  category colours and post counts. Enabled by default; uses the bundled
  `tags/danbooru.csv` or any tagcomplete-format CSV you point it to.


## Usage
1. Make dataset
    - better to use already cropped images
1. Load them
    - use interrogator if needed
1. Edit their captions
    - filter images you want to edit by tags in "Filter by Tags" tab
    - filter images manually in "Filter by Selection" tab
    - replace/remove tags or append new tags in "Batch Edit Captions" tab
    - edit captions individually in "Edit Caption of Selected Image" tab
      - you also can use interrogator here
    - move/delete files in "Move or Delete Files" tab if needed
1. Click "Save all changes" button


## By the way, how can I edit tags quickly?

Basic workflow is as follows:

1. Filter images
1. Batch edit

Please note that all batch editing will be applyed **only to displayed images (=filtered images)**.

### 1. Which filter is appropriate?
#### I want to edit all at once  
  No filter is required.
#### Some images require editing    
  1. **They should / shouldn't already have same tag(s)**  
    Go to "Filter by Tags" so that the only images to be edited are displayed.
  1. **They have nothing in common**  
    Go to "Filter by Selection" and apply.  
    Images can also be added to the filter by pushing [Enter] key.

### 2. How can I edit as I want?
  ![](pic/ss07.png)  
#### I want to add some new tags  
  1. Go to "Batch Edit Captions" tab
  1. Append tags to "Edit tags" textbox
  1. Push "Apply changes to filtered images" button  
  ![](pic/ss08.png)  
  "foo" and "bar" will be added to all images displayed.

#### I want to replace the tags which are common to displayed images  
  1. Go to "Batch Edit Captions" tab
  1. Replace tags in "Edit tags" textbox
  1. Push "Apply changes to filtered images" button  
  ![](pic/ss09.png)  
  "male focus" and "solo" will be replaced with "foo" and "bar".

#### I want to remove some tags  
  The same as replacing. Just replace the tags with "blank".  
  Also you can use "Remove" tab in "Batch Edit Captions".  
  ![](pic/ss10.png)  

#### I want to remove redundant generic tags automatically
  Use the "Smart Dedup" tab in "Batch Edit Captions". When a caption contains a
  specific tag, the generic tags it implies are removed, e.g.:
  - `white thighhighs` → removes `thighhighs`
  - `white panties` → removes `panties` and `underwear`
  - `rose` → removes `flowers` / `flower`

  Two methods are available:
  - **Rules (offline)**: a built-in implication table plus a `<color> <noun>`
    heuristic. No network needed. You can extend the table with a JSON file
    (Settings → "Smart Dedup custom rules JSON file"):
    ```json
    {
      "implications": {
        "white thighhighs": ["thighhighs"],
        "rose": ["flowers", "flower"]
      }
    }
    ```
  - **LLM API**: let a chat model decide. Set the API type (`openai` for any
    OpenAI-compatible server such as llama.cpp / Ollama / vLLM / OpenAI, or
    `anthropic`), base URL, model name and API key in Settings. Identical tag
    sets are cached so each unique caption is sent only once.

#### I want tag autocompletion while typing
  Autocompletion is **on by default** in the caption textboxes (Caption of
  Selected Image, Interrogate Result, Edit Caption, and the batch Edit Tags box).
  Start typing a tag and a dropdown of matching Danbooru tags appears:
  - suggestions are coloured by category (general / artist / copyright /
    character / meta) and show the post count;
  - aliases are searched too (e.g. typing `high_res` offers `highres`);
  - use ↑/↓ to choose, Enter or Tab to insert, Esc to dismiss;
  - the inserted tag uses spaces instead of underscores and is followed by `, `.

  Configure it in **Settings**:
  - **Enable booru tag autocompletion...** — turn the feature on/off.
  - **Tag autocomplete CSV file** — leave empty for the bundled `tags/danbooru.csv`,
    or point to any [tagcomplete](https://github.com/DominikDoom/a1111-sd-webui-tagcomplete)-format
    CSV (e.g. `e621.csv` or a custom/translation file from an existing tagcomplete
    installation). Relative paths are resolved against the repo root.
  - **maximum number of suggestions**, **also search tag aliases**,
    **insert tags with spaces**, **append a comma and space** — tune the behaviour.

  The tag data is served locally; no network access is needed. The bundled
  `danbooru.csv` is from the MIT-licensed tagcomplete project (see `tags/README.md`).

  Press **Preview** to see what would be removed, then **Apply to filtered
  images**. Changes are not written to disk until "Save all changes".

#### I want to add/replace/remove tags more flexibly  
  1. Go to "Batch Edit Captions" tab
  2. Use "Search and Replace" with "Use regex" checked  
  ![](pic/ss11.png)  
  "1boy", "2boys", … will be replaced with "1girl", "2girls", … in each tags of images displayed.  
  A comma will be regarded as the sepalator of two tags.  
  By using regex, you can add/replace/remove tags according to more complex conditions.


## Hybrid captioning for DiT trainers (Anima / MOSS)

CLIP-based trainers (SD 1.5 / SDXL / Illustrious / Pony) want short comma-separated
booru tags; DiT trainers with LLM text encoders (Anima, MOSS) want descriptive
natural language. This fork lets you maintain **one master caption set** and
derive both formats automatically:

```
img.png
img.txt       <- pure tags (edited in this app; used as-is by SD/Illustrious/Pony)
img.nl.txt    <- natural-language caption (VLM-generated or hand-written sidecar)
img.multi     <- derived candidates for kohya sd-scripts multi-caption training
```

`img.multi` contains complete caption candidates separated by `---===---` lines;
sd-scripts randomly picks one per training step. Example:

```
masterpiece, best quality, score_7, safe, 1girl, long hair, school uniform, classroom
---===---
masterpiece, best quality, score_7, safe, 1girl, long hair, school uniform, classroom. A girl with long hair stands in a sunlit classroom, wearing a navy school uniform with a red ribbon.
---===---
A girl with long hair stands in a sunlit classroom, wearing a navy school uniform with a red ribbon. Soft afternoon light falls across the desks behind her.
```

Workflow:

1. Tag and edit captions as usual; **Save all changes** writes the `.txt` files.
2. Open **NL & Multi Captions** → *Generate NL captions*. Configure the VLM
   (base URL / model / API key) there or in **Settings** (*NL Caption VLM …*).
   Any OpenAI-compatible **vision** server works: Ollama, llama.cpp (`llama-server`),
   vLLM. For NSFW datasets use an uncensored/abliterated VLM (e.g. an uncensored
   Qwen3.5-35B-A3B) so captions are not refused. Existing tags can be sent as
   hints. Results are saved to `<img>.nl.txt` and can be reviewed/edited per image
   in *Edit Caption of Selected Image → VLM NL Caption*.
3. *Generate .multi* combines the edited `.txt` tags (or the current in-editor
   tags) with the NL sidecars. Options: which candidates to include (tags only /
   tags+NL hybrid / NL only), tag style inside `.multi` (spaces for Anima/MOSS,
   underscores for raw booru), a quality prefix (e.g.
   `masterpiece, best quality, score_7, safe`), and whether to prepend it to the
   NL-only candidate. `score_*` tags keep their underscores in space mode.
4. Re-run step 3 any time after editing — `.multi` is always re-derivable from
   `.txt` + `.nl.txt`; only the master data needs maintenance.

### Serving the NL captioner (verified model choices)

The base model **Qwen/Qwen3.5-35B-A3B** is natively multimodal (vision encoder
built in — there is no separate "VL" variant), 35B total / 3B active MoE.
Uncensored options that keep vision working:

- **Ollama (easiest):** `ollama pull huihui_ai/qwen3.5-abliterated:35b`
  (Q4_K_M, ~24 GB, text+image input; needs Ollama ≥ 0.17.5). Higher quality:
  `huihui_ai/qwen3.5-abliterated:35b-a3b-q8_0` (~39 GB). Then set
  *NL Caption VLM base URL* to `http://<host>:11434/v1` and model to
  `huihui_ai/qwen3.5-abliterated:35b` (the app default).
  Higher-quality custom import (Q6_K/Q8_0, auto-split across GPUs; the two
  `FROM` lines load model + vision projector):
  ```bash
  hf download mradermacher/Huihui-Qwen3.5-35B-A3B-abliterated-GGUF \
    Huihui-Qwen3.5-35B-A3B-abliterated.Q6_K.gguf \
    Huihui-Qwen3.5-35B-A3B-abliterated.mmproj-f16.gguf --local-dir ./q35
  printf 'FROM ./q35/Huihui-Qwen3.5-35B-A3B-abliterated.Q6_K.gguf\nFROM ./q35/Huihui-Qwen3.5-35B-A3B-abliterated.mmproj-f16.gguf\nPARAMETER num_ctx 32768\n' > Modelfile
  ollama create qwen3.5-35b-abliterated -f Modelfile
  ```
  The long silent "gathering model components" phase is SHA-256 hashing of
  20–30 GB, not a hang.
- **llama.cpp (best community reputation for NSFW captioning):**
  `HauhauCS/Qwen3.5-35B-A3B-Uncensored-HauhauCS-Aggressive` GGUF — download the
  main quant **and** the `mmproj-…-f16.gguf` vision projector (required for
  image input), then:
  `llama-server -m Qwen3.5-35B-A3B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf --mmproj mmproj-Qwen3.5-35B-A3B-Uncensored-HauhauCS-Aggressive-f16.gguf --jinja -c 8192 --port 8080`
  and point the app at `http://<host>:8080/v1` with the model name you passed
  (or the default alias). Q4_K_M ≈ 21 GB + 0.9 GB mmproj fits a 24 GB GPU;
  Q8_0 ≈ 37 GB suits 48 GB+ or unified-memory boxes.
  Shortcut on recent llama.cpp builds (auto-downloads the matching mmproj):
  `llama-server -hf HauhauCS/Qwen3.5-35B-A3B-Uncensored-HauhauCS-Aggressive:Q6_K --jinja -c 8192 --port 8080`
  (or `-hf mradermacher/Huihui-Qwen3.5-35B-A3B-abliterated-GGUF:Q8_0`). If image
  requests still 500 with "image input is not supported", pass `--mmproj`
  explicitly. Needs a build with qwen3_5_moe / Gated-DeltaNet support.
- vLLM: serve `huihui-ai/Huihui-Qwen3.5-35B-A3B-abliterated` (BF16, ~67 GB).

Notes:

- Keep **thinking mode off** for batch captioning (the app default) — cleaner
  single-paragraph output; enable it in Settings if you want deeper reasoning.
- Avoid temperature 0 with quantized Qwen3-family models (repetition loops);
  the app sends Qwen3.5's official non-thinking sampling: temp 0.7, top_p 0.8,
  top_k 20.
- Abliteration removes refusals, but community reports say the huihui build's
  NSFW *visual vocabulary* can be shallow; the HauhauCS Aggressive build is
  preferred for explicit datasets. Test a few samples before batch-running.

### Tagger notes

- **PixAI Tagger v1.0** runs from the DirectML-validated ONNX export
  `Mexes/pixai-tagger-v1.0-onnx-fp32-fp16-int8` (fp16 on GPU, fp32 on CPU;
  ~947 MiB download on first use). It uses the official per-category
  thresholds internally (character 0.27, style 0.15, copyright 0.24, meta
  0.17, rating argmax); the *PixAI General Tag Threshold* slider (default
  0.17) tunes only the general category. Rating tags are included only when
  *Use Rating tags* is enabled in Settings.
- WD v3 / large timm taggers keep the single WD threshold slider as before.
- Tagging speed: the default `onnxruntime` wheel is CPU-only (~11 s/image
  for PixAI on a desktop CPU). For GPU acceleration swap the package (the
  taggers automatically prefer CUDA / DirectML when present):
  Windows `uv pip uninstall onnxruntime && uv pip install onnxruntime-directml`
  (any DX12 GPU), Linux+CUDA `onnxruntime-gpu`. Note `uv sync` reinstalls the
  CPU wheel from `pyproject.toml`, so re-apply the swap after syncing.

Training-side notes (kohya sd-scripts):

- Point the dataset at `caption_extension = ".multi"` for Anima/MOSS. A dataset
  cannot load `.txt` and `.multi` simultaneously — keep a pure-tag candidate in
  `.multi` (the default) to retain tag-style training signal.
- Anima: do **not** cache text-encoder outputs (candidates are sampled randomly
  per step, a cache would freeze one candidate). MOSS: TE caching is fine.
- SD/Illustrious/Pony keep using the plain `.txt` files unchanged.


## Trouble shooting
### Cannot see any image in dataset and no error is shown
(maybe in >= v0.0.6)  
If you want to load images from other directory than this app, you should register the directory in whitelist in the "Settings" tab, or use temporary image file (as same as the next section).  
Input path in "Path whitelist to show images …" and save settings.  
You can input drive name like "C:\\" (Windows).  
![](pic/ss12.png) 


### Cannot see any image in dataset and saying "All files must contained within the Gradio python app working directory…"
(maybe in <= v0.0.5)  
Set folder to store temporaly image in the "Settings" tab.  
Input path in "Directory to save temporary files" and check "Force using temporary file…" and save settings.  


### So laggy when opening many images or extremely large image
Input non-zero number in "Maximum resolution of ..." in the "Settings" tab to use smaller thumbnail for the image gallery.  
It may not work with dataset with millions of images.  
![](pic/ss13.png) 


### My PyTorch is working without CUDA
The default install is CPU-only PyTorch. To switch the private `.venv` to a CUDA build:
```sh
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
uv run --no-sync scripts/launch.py
```
`--no-sync` keeps the CUDA build instead of restoring the locked CPU one, so launch with
`uv run --no-sync scripts/launch.py` (`launch_uv.bat` would re-sync the CPU pins).
